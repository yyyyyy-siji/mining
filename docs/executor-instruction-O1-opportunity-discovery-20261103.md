# O1 执行指令：真实材料到候选产品机会

日期：2026-11-03

## 授权与目标

用户已明确当前用途是“从公开社区和评论中，找值得开发的产品或功能机会”，并于本轮同意最小优化后要求开工。项目保持通用产品机会发现定位，不硬编码某个行业；首轮采样范围是验证范围，不是产品范围限制。

本项是小批候选分析功能，不修改顶层需求，不宣告 P13 金标、校准、语义去重、增量聚类或数据版本阶段通过。保留既有完整管线和安全熔断。

## 当前事实

- Git 根目录为本文件所在项目；已有大量未提交改动，必须逐块保留，禁止 reset/clean/checkout/批量格式化/提交。
- 默认 DeepSeek 没有真实 Embedding，现有 runner 会跳过聚类和资产生成。
- 原聚类和资产生成存在全库选择；本功能不得调用这条路径来分析本批输入。
- 已有真实 URL 导入门禁、原话匹配函数和来源展示，可以复用。
- 用户强调减小工作量，不建设审批、复杂评分、多人协作、版本回滚或新的 PRD 功能。

## 最小实现

### 1. 显式候选发现服务和接口

在现有机会相关路由加入 POST `/api/v1/opportunities/discover`，另建小型 service 模块处理本批材料。请求必须指定本批 `feedback_ids`，数量有明确小上限（例如30）；校验所有ID存在且为 `product_feedback`。不得默认扫描全库。

从所选 RawFeedback 原文做一次结构化文本候选归纳，复用运行时文本 LLM。它是待人工验证的文本建议，不声称做过 Embedding 去重/聚类。可对完全相同原文做确定性去重，但不能删除或改写库内任何记录。

结果最多3个，允许0个。每个候选包含：目标人群与场景、具体痛点、最小产品/功能设想、提出它的理由、待验证问题、原文证据。明确区分原始事实与系统推断，付费意愿或普遍性未知时不得编造。不得输出综合机会百分比或校准概率。

模型只返回证据对应的反馈ID和quote；URL、来源等必须从当前选中记录回填。每条quote必须通过现有确定性原文匹配；未知ID、跨批证据、伪造原话、无合规来源均不得显示成有效证据。无有效证据的卡片不得推荐；返回清楚的排除/不足信息。不用摘要冒充原话。机会仅作为本次预览返回，不创建 Theme/PainPoint/Requirement，不改任何 processing/reviewed 状态，不调用原全库语义流程。

输入/模型异常应有用户可理解的错误，输入过长应明确拒绝或明确告知分析范围，禁止静默忽略选中材料。使用现有代码块清理与结构校验方法。保留来源原文以抵抗材料内的指令注入，不赋予材料工具执行权限。

### 2. 在现有机会页提供入口

在现有SPA机会页内增加“选择已导入材料→发现机会”的小区域，列出本次可选的产品反馈（标题/预览/来源），可勾选、显示选中数量、最多3张候选。不要让用户手输数据库ID。

展示“原文依据 / 系统建议 / 待验证问题”，复用来源按钮；所有模型和外部文本必须转义。提供诚实的空结果、加载失败与重试状态。现有持久化机会和视频模式保持可访问；历史机器状态不能当人工审核。候选不显示固定0.5优先级。Streamlit可增加同等小入口或最小兼容提示，避免宣称未实现的一致功能。

人工保留/排除本轮先用导出的可读清单或本地会话记录即可，不新建审批/状态机。

### 3. 一个真实材料采集脚本

新增一个小型 `scripts/collect_community_opportunity_samples.py`（可原名为 `collect_hn_opportunity_samples.py`），用已验证可访问的HN Algolia API读取Ask HN/评论样本；另支持 `--source v2ex` 从官方公开 Atom feed 读取中文帖子，不扩展多平台框架。支持可选query、days、limit及显式输出路径，限制请求/样本数量和超时。保留直达原帖/评论URL、原文、父帖信息（如有）、发布和采集时间、平台ID、API/feed来源；正确清理HTML实体和标签。

输出现有 `/feedback/batch` 可接受的JSON数组。HN/V2EX尚无专属策略时，使用现有策略允许的source/capture组合（已确认custom+official_api可用，manual不允许official_api），并用准确source_note/raw_payload标注平台及API/feed方式。只写用户指定的文件，不自动入库、不调LLM、不修改.env、不把公开可读标作正式金标授权。附带采集摘要，包括实际抓取数、跳过数和错误；失败返回非零，禁止写PASS。

数据源可用性必须写实：HN本轮可匿名读取但有技术人群偏差；V2EX公开RSS已实测HTTP200，但只是有限帖子流而非完整历史/全部评论采集；GitHub当前匿名请求403，需适当只读凭据和额度；其他中文社区/评价首轮支持用户可访问的原文+链接导入，不能称为自动全站采集。

## 验收

1. 无真实Embedding能力的文本LLM也可生成本批候选；旧管线熔断测试不回归。
2. 未知/跨profile ID、跨批证据、编造quote、无证据卡、全重复输入、空结果及模型异常均有真实业务断言。
3. 用临时数据库证明本批隔离，且新路径不新增/改写任何源记录、Theme、Requirement或审核状态。
4. 前端可选择材料和查看证据；外部/模型HTML不可执行，失败后可重试。
5. 采集脚本有有界分页、失败/空结果/HTML清理与输出契约检查；实际采集另标LIVE，mock仅标测试。
6. 对改动文件运行ruff和node语法检查，并执行相关旧证据链、来源、Embedding安全及PRD回归。失败定位，不擅自扩大修改。
7. 真实LLM冒烟最多做一小批，使用现有已配置文本模型、临时DB/独立输出，不打印密钥；外部不可用时标BLOCKED，不用mock假充LIVE。
