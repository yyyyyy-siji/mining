# 从社区材料开始发现机会

在产品反馈模式打开“数据源”页，顶部“社区材料采集”区域可以直接取得第一批原文，无需先运行脚本。

1. 选择来源。默认 V2EX“问与答”、30 天、最多 10 条，不预设行业关键词；HN 可选择 Ask HN 帖子、评论或二者。
2. 点击“采集预览”。此时只读取外部公开材料，不入库、不调用模型。核对标题、正文、原帖链接、真实发布时间和采集时间，再勾选需要保留的条目。
3. 点击“导入所选材料”。这是明确的数据写入操作；成功后会显示处理后的可用材料数。已有相同文本可能复用旧 ID，因此处理数不能当作新增数或独立用户数。
4. 导入后页面会按返回 ID 回读实际已存原文和来源；点击“用本批材料发现机会”，把这些精确 ID 带到机会页，不会自动分析。若回读失败，可以只重试回读，不用再次导入。
5. 在机会页核对选择，再手动点击“发现机会”。此操作会调用现有文本模型，至多生成 3 个待验证候选，也允许没有候选。人工判断与备注可下载清单，刷新页面前请先导出。

切换采集条件需重新预览。新的批次会替换当前预览；跳转机会页前会提示替换旧选择、旧候选及人工备注。预览和判断都是页面会话态，不是长期保存的研究报告。

## 来源覆盖

- V2EX 只读取“问与答”或“奇思妙想”的一个当前公开订阅流；不含完整历史或评论。关键词仅过滤当前订阅流，不是全站搜索。缺少有效发布时间的条目会跳过，更新时间不会被冒充为发布时间。
- HN 使用 Algolia API 查找 Ask HN 和/或 HN 评论；评论来自整个 HN，不只 Ask HN。网页最多 3 次请求，可能在达到条数前用完预算。
- 两源都偏技术社区，不能代表所有消费者，也不能单凭帖子数证明市场规模或付费意愿。
- 网页仅支持这两个固定来源，不支持任意 URL 抓取。来源失败会明确报错；忙碌时稍后重试。单响应最多接受 2 MB，整批最多 6 MB。HTTP 等待超时不意味着同步网络线程已被强制终止。

其他社区仍可在“数据导入”提供你可访问的原文和直达链接。原有 CLI 脚本继续保留，参数和 JSON 导出方式不变。
