# D3-M3 执行指令：复验现有Chrome采集路径的可重复性

日期：2026-11-10。

## 任务目标

基于已验证的当前Chrome界面读取路径，复验另一篇国内小红书材料的读取、来源和去重是否可重复。继续使用用户已经打开的页面；不再研究怎样登录、不新开登录窗口。

## 背景 / 当前结果

D3-M2通过了1篇描述正文、3条已加载评论 → 真实ID → 4快照 → 2个候选预览及3处逐字引用。本轮是Codex辅助读取和项目已有导入/分析链，不是MediaCrawler一键采集成功。原材料带独立ID的正文可条目定位，评论仅父页面；评论ID、层级、精确源时间未知。

当前已有“作者介绍的现成插件”进入候选，说明下一轮应优先选择明确表达尚未解决困难的材料，同时保持采集功能验证与市场判断分开。

## 允许修改范围

本阶段默认不改应用代码。Commander可以用CUA操作当前Chrome页面、写真实材料包、使用隔离服务已有批量接口、回读快照并保存报告。如暴露具体实现错误，单独写窄范围返修指令给现有Executor。

## 禁止修改范围

不新开独立浏览器、不重新协调登录、不复制账号Cookie、不启用主Chrome远程调试、不安装扩展或改网络/TLS。不读取私信/通知/账号设置，不把网页AI摘要纳入原文。不操作业务库或写入正式需求资产，不新增代理。

## 执行要求

1. 先使用已绑定的当前Chrome页面和最新UI状态。一次只选一篇实际返回的笔记，最多3条已加载评论，不自动展开楼中楼、不下载媒体。
2. 把原文、访问链接、对象ID、真实采集时间、覆盖边界写入材料包。评论ID/层级/绝对时间无法从本次可见材料确认时保持unknown/null，不用序号或推断冒充平台ID和源时间。
3. 使用隔离服务/库；首次导入核对新增数，再重复提交同一包核对0新增和原ID/快照不变。批量回执总数必须等于新增加重复；不能仅凭“返回了ID”认定新增。
4. 仅有新的、具体的困难证据时才显式分析一次，核对引用来自正文；已有解决方案、单一来源、泛泛赞美都要如实说明。不要为了候选数量扩大结论。
5. 若需要把“辅助读取”做成项目内自动复用普通Chrome的按钮，先提交独立小方案，列清连接机制和必要权限；不要用手动材料包演示冒充该按钮已经支持，也不要在未准备可核验产物时让用户反复处理浏览器设置。

## 验收标准

### 静态 / 回归

无源码改动时不重复跑已通过的445/26测试。若发现新缺陷，先指令再改动，并运行与该缺陷相关的有意义检查，保留命令退出码。

### 功能

分别记录搜索、正文、评论、导入ID、来源快照、去重和候选引用。缺失项标明pending/failed；界面辅助读取、项目一键采集和平台全量覆盖分别说明，不能互相替代。

### 交付门禁

报告中的笔记ID、反馈ID、截图、机读结果、快照SHA与实际文件一致。收尾只清理自己的采集任务，保留用户原窗口；若留本地核对服务，列明地址和用途。

## 交付报告

写 `docs/acceptance-D3-M3-existing-chrome-batch-YYYYMMDD.md`，列真实新增材料和验证结果、可重复性结论、仍未知字段及自动入口差距。通过后再选择下一个国内平台的小样本实采，不开展海外来源工作。
