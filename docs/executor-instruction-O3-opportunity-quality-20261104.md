# O3 下一步指令：验证挖出的机会是否有用

状态：后续工作准备，**本轮未执行**。不新增应用功能。

## 任务目标

O1/O2 已解决真实材料→网页采集导入→可追溯候选的可用流程。下一步验证候选能否帮助用户判断值得开发的产品/功能，避免继续扩展工程而没有实际研究收益。沿用项目通用定位，不要求用户先指定行业。

## 范围

仅通过已有有界采集、候选预览和人工审阅，形成一个小批次机会研究报告。使用独立临时数据库或明确的用户批次，不改代码、MASTER、P13冻结计划、业务数据库、密钥、评分或聚类规则。不创建定时任务，不联系作者或其他人。

## 实施要求

1. 使用现有支持的来源，收集合计最多30条公开原文。明确平台、时间窗口、帖子/评论类型及请求次数；V2EX仅当前feed，不能声称全站或历史覆盖。不得为凑数量编写材料。
2. 阅读原文，将新闻/自推/泛讨论和具体使用困难区分；记录选择与排除理由。技术社区样本不能冒充普通消费者代表性样本。没有具体困难时允许无候选。
3. 用已有页面/API得到至多3个候选，逐项核对原话、URL、场景、当前解决办法。模型归纳与方案设想必须与原文分开。
4. 对保留的候选做一次有界公开核查：查现有替代工具或产品官方文档，说明候选可能已有解决方案、剩余缺口及不确定之处；引用真实链接，不从营销文案推导已验证需求或付费意愿。
5. 报告优先写“为什么值得继续了解/为什么暂时放弃”，给下一项最小验证动作；避免虚构市场规模、概率、独立用户数或综合评分。联系用户、收费测试等仅提出，不擅自执行。

## 验收标准

- 原始材料、选择/排除记录、候选导出和核查链接可检查。
- 每个保留候选都有真实依据、已有替代方案、尚未证实的关键假设、继续或放弃的明确理由。
- 允许0候选；不得把“程序成功生成”算作“机会质量通过”。
- 输出 `docs/opportunity-quality-O3-<date>.md` 和相关证据清单，说明哪些判断仍需用户审阅。

本指令准备下一项研究工作，不表示已取得新的真实用户验证结果。
