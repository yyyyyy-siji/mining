## 执行步骤

1. 读取D1最终验收、用户说明和官方当前文档，确认Code/字段/授权要求是否改变。新建独立SQLite和本地端口；只读取配置是否存在，不输出凭据。
2. GET知乎status。configured=true仅代表本地存在配置，不能在成功响应前标记“实网通过”。确认无鉴权访问仍受既有API权限约束。
3. 用户选择或现有项目定义中取一个研究词；单次检索最多3条，保留Query/Count/SortBy、SearchHashId、原始URL、ContentID、CreateTime/更新时间和采集时间。按实际结果记录成功、空结果、鉴权、限流或额度问题，不把错误记成empty。不会自动重试付费/配额请求。
4. 在网页确认摘要、精选评论只显示为线索，不入待分析反馈，不调用模型。下载线索JSON，检查无Secret/Authorization，链接与内容类型及ID一致。
5. 如用户已经有一条可见实际原文，使用现有“补原文”入口保留原始线索并提供真实正文；未知评论ID、作者、时间留空。需要登录、原文不可见或正文未取得时，如实记录原文链尚未完成，不用摘要替代。
6. 在临时库验证预览→明确导入→详情→JSON快照的一致性；重复同对象同文复用ID，正文变化保留旧版，只有父页的评论明确定位限制。
7. 仅对实际原文明确发起一次机会预览，检查quote_field、feedback_id、URL及snapshot_hash均来自所选材料。结果可以0张；不为得到候选而降低门槛，不把候选当市场验证。
8. 关闭临时服务和本轮创建的页面，保留证据与隔离库；不触碰用户原有标签页或服务。

## 验收标准

- 文档阅读、mock离线测试和真实授权响应分别标记。
- 真实搜索成功需HTTP和业务Code成功、结构/来源校验通过；空结果只证明该查询正常返回，不能证明原文闭环。
- 原文闭环需实际正文及留存快照；缺正文就明确部分完成。
- 摘要/精选评论不能进入原文分析；快照不一致的材料被排除。
- 完整导出不含凭据；预览不写库，候选不创建正式资产。
