# D3-M4 执行指令：B站小样本文本来源验证

日期：2026-11-10。

## 任务目标

在D3-M3选定片段范围的可重复性通过后，验证B站1个真实内容页面及最多3条已加载评论的文本留存、隔离导入和重复处理。优先选择描述具体困难的内容，不能用候选数量作为质量目标。

## 背景与当前边界

小红书已有两批共8条真实材料；D3-M3长正文读取发生截断，已明确按片段留存。两项模型候选主要来自现有产品推广，不能证明未满足需求。原Chrome登录窗口保留；不要恢复登录方式排查。

## 允许范围

- Commander使用CUA操作用户现有普通Chrome；先读最新状态。进入B站可在同一Chrome创建一个普通标签页，保留原小红书标签页，不打开独立浏览器。
- 写材料、证据、验收和下一阶段文档；使用已核对的18817隔离服务及已有接口。
- 仅在发现新的具体实现错误后，先写单独窄范围返修指令，再交Executor修改，不由Commander直接改源码。

## 禁止范围

不修改应用源码，不操作业务库，不复制Cookie或开启主Chrome调试，不改网络/TLS、不安装扩展。不下载视频、音频或图片，不展开楼中楼，不读取账号私信或通知，不把AI总结或字幕推测当作说明区原文。验证或登录出现真实阻挡时记录当前页面，不绕过、不反复开登录窗口。

## 执行要求

1. 一次只取1个实际搜索返回的B站页面。记录本轮是否真的提交新搜索，不能把沿用旧结果写成搜索复验通过。没有可读取的具体原文时允许0条入库并说明原因。
2. 保留页面链接、真实BV/av等可确认对象ID、实际采集时间、原文和精确覆盖范围。长文本先检查首尾完整；若界面接口截断，显式标为片段，保留上下文截图，不能自行补写成全文。
3. 最多选择3条已加载评论；未知评论ID、层级、精确源时间保持null/unknown。说明是否有表情图片未进入文本、来源只能父页面定位等边界。
4. 用 `POST /api/v1/feedback/batch` 导入原文材料数组。首次核对 `total=ingested+duplicates` 和真实数据库增量；重交同包必须0新增，ID顺序、快照SHA及完整快照不变。旧8条材料也不得改变。
5. 仅存在新的具体困难证据时，显式触发一次所选材料的机会预览。逐字核对所有引文，并把“现有产品介绍”“情绪表达”“尚未解决的困难”分别判断；已有解决方案不能自动变成新开发建议。0候选可为正确结果。
6. 若分析，优先使用UI现有下载按钮保存候选清单，核实下载事件和实际文件。不要第二次调用模型来补证据，也不要将截图当作已成功导出。
7. 对每个候选另写 `candidate-admission.json`，列 `concrete_pain_quote`、`current_solution`、`remaining_gap_quote`、`admit_for_further_validation` 和理由。两个quote非空时都必须逐字命中本批正文；缺少现有方案仍未满足的困难证据、或引文仅为正面功能介绍时，`admit_for_further_validation=false`。这只是本轮人工验收门禁，不冒充项目已经自动过滤。采集链通过与候选准入分别给出结论。

## 验收标准

### 功能与来源

分别记录搜索、内容文本、评论、导入、去重、快照、引用和导出。每项使用passed/failed/pending/skipped及明确范围；片段留存通过不能扩展为全文通过。

`GET /api/v1/feedback/{id}/source-snapshot` 必须回读原文与元数据，核对verified及两个SHA matches。候选证据必须来自本批真实ID，quote逐字包含于对应 `content.text`，quote_field及snapshot_hash一致。哈希仅证明留存一致。

### 回归与静态检查

无应用源码改动时不重复跑445/26历史测试；独立材料断言保留真实退出码。若出现源码返修，按具体缺陷运行有意义的受影响检查，不得改历史测试以迁就实现。

### 交付门禁

报告、材料包、候选导出、截图、机读结果及SHA必须一致。保留用户原窗口；只清理本轮自己创建的任务和临时服务，列清保留服务地址与用途。不得把界面辅助读取写成项目一键采集成功。
