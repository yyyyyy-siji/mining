# 国内来源接入与留存说明

本轮先完成接入准备，不需要现在申请账号或填写密钥，也没有执行带密钥的真实知乎搜索。

## 目前怎样取得材料

- **V2EX**：继续使用“数据源”页的现有社区采集，取得当前“问与答/奇思妙想”订阅流材料。原文、对象 ID、真实创建/采集时间、平台和原始响应会随导入留存。订阅流的 summary 不能冒充 content，本轮将只有摘要的条目明确跳过。
- **知乎**：“知乎官方搜索（检索线索）”已准备。缺少本机配置时显示“未配置”，禁用误导性搜索；API 返回明确 503，而且不会联网。配置存在也只代表准备好本机配置，不表示真实授权接口已经验证通过。
- **小红书/B站及其他可见页面**：仍可人工提供少量实际用到的正文和原始链接，补充评论/对象 ID、父页面、源时间和截图/OCR 信息。本轮没有增加自动登录、验证码处理或全站采集。

## 后续具备知乎凭据时

由你在知乎开发者平台按官方流程取得访问资格与 Access Secret，再在**本机服务端**设置环境变量 `ZHIHU_ACCESS_SECRET` 并重启服务。不要在网页、URL、聊天、localStorage 或可分享文件填写密钥；本轮程序也没有增加密钥输入框。

可先读取受既有 API 鉴权保护的 `GET /api/v1/connectors/zhihu/status`，它只返回配置是否存在、能力和限制；不会返回密钥或发送知乎请求。随后再另行进行真实授权运行验证。

搜索使用一个固定官方端点，单次最多 10 条；关键词必填，时间范围按源创建时间筛选。返回 `ContentText` 是摘要，精选评论没有独立评论 ID、作者或时间，因此都只是线索。可以打开原页面、下载完整线索记录，再用“补充原文”入口提供实际正文；程序不会把摘要自动填入原文框或自动分析。

## 怎样追溯一条候选

导入时服务端保存版本化来源包和 SHA-256，记录正文、对象/父对象身份、原始 URL、内容性质、源创建/更新时间、采集时间、采集方式和原始 payload。缺少的作者和时间保留未知，人工提供的材料明确未联网核验。

在反馈或候选处查看来源快照并下载 JSON，可以检查当时留存的内容。界面“完整性一致”仅说明当前记录与保存哈希相符，不证明平台真实性、网页永久可达、人工已审核或市场需求成立。旧记录没有来源包时会显示“历史文本，未记录快照”，不会自动补造。

候选原话只匹配该对象的单一正文字段，不能引用父帖标题或生成标题。摘要、精选评论、快照不一致的材料不能作为机会原文依据；只有父页面链接的评论会明确“仅定位父页面”。

同文不同页面/平台/评论身份分别保存；同对象同正文重复导入会复用首次留存记录，正文变化则新增一版，保留旧出处。页面按实际返回 ID 回读已存内容，不用新预览链接替换旧记录来源。
